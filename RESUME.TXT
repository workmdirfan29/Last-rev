6. INTERVIEW Q&A CHEATSHEET
--------------------------------------------------------------------------------

Q1: Why did you choose a Local-First architecture instead of a backend database?
A1: To provide zero-latency responses, eliminate recurring server hosting costs, and guarantee 
    100% user data privacy. By implementing the Repository Pattern over IndexedDB (Dexie.js) and 
    Zustand, all data remains strictly within the learner's browser with full JSON export/import 
    capabilities.

Q2: How did you implement the Linux terminal inside the browser?
A2: I built an in-memory Virtual File System (VFS) simulating directory nodes, file contents, and 
    permissions in TypeScript. A custom lexer and execution engine parses user input, handles pipeline 
    chaining (|), and implements standard POSIX commands (cat, grep, head, tail, wc, sort, uniq, bc) 
    without any remote Docker or virtual machine instances.

Q3: How does your readiness score work?
A3: It follows a transparent formula: Area Score = (60% * Completion) + (40% * Confidence). 
    Completion measures questions attempted versus total catalog items; confidence measures the 
    normalized sum of 1-5 self-ratings. This prevents superficial completion from inflating scores.

Q4: How did you optimize bundle size with 80+ content modules?
A4: I utilized Vite's import.meta.glob for lazy chunk loading. During build time, a script generates 
    a lightweight index (index.generated.ts) containing only metadata (IDs, titles, tags). This allows 
    the global Command Palette (Cmd+K) to perform instant search without preloading module bodies.

7. STAR METHOD BEHAVIORAL STORIES
--------------------------------------------------------------------------------

Story 1: Performance & Code-Splitting (STAR)
• Situation: The platform needed to support 80+ engineering modules and thousands of questions. 
  Bundling everything statically caused unacceptable initial bundle sizes and slow FCP.
• Task: Keep initial bundle size minimal (<200KB initial chunk) while retaining instant global search.
• Action: Separated module questions into dynamic lazy chunks using import.meta.glob and created a 
  build-time generator script to produce a lightweight metadata index.
• Result: Reduced initial JavaScript load dramatically, achieving sub-second page loads and instant 
  Cmd+K global search.

Story 2: Privacy-Preserving Architecture (STAR)
• Situation: Users are hesitant to upload resumes containing personal contact info to unknown backends.
• Task: Provide resume skill gap audits against target job descriptions without compromising privacy.
• Action: Integrated pdfjs-dist directly on the client side using Web Workers to extract text in-browser, 
  tokenizing skills against an 80+ module taxonomy locally.
• Result: Delivered 100% privacy-compliant, zero-latency resume analysis with zero cloud storage costs.
